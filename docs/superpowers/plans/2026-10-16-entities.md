# Entities (#41) Implementation Plan

**Spec:** GitHub issue #41 and its five comments (the decisions: fully automated tagging, merge, `topic` kept, back-fill, what `context` needs). #4 is closed as a duplicate of #41.

**Goal:** One list of people, places, projects and topics (`entities`). Each record links to the entities it names (`record_entities`). The agent sets the links on its own.

**Order of work.** Each slice is one or two commits, with tests first, and `make test` green before the next slice.

## Scope of this build

In: schema and migration 00008, the `entity` record type, links, the project of a todo, tagging through the write tools, the tools `tag`, `entity` and `merge_entities`, `MergeEntities`, entities in `context`, the admin page for entities, instructions, README and AGENTS.md.

Out (each named in the issue, left for a later build, and written on #41 as a comment):

- `lifeos job tag-backfill`: it needs the job rails and the place where `claude -p` runs (#38).
- The duplicate run: it moved to the daily lint of #42.
- Facts with dates (the step after this issue).
- The filter of `search` by entity (#13).
- The `wiki_lint` checks of `wiki_path` (an entity that a page names with no `wiki_path`, and a `wiki_path` with no page).

## Rulings

- **R1. Slices as above.** The tagging in the write tools is one slice, because every tool takes the same `entities` input.
- **R2. `Todo.Project` stays a string**: the name of the project entity. The REST API, the admin pages and the tools keep their `project` field. The service resolves the name to an entity (and creates it when there is none), so no caller changes.
- **R3. Reads of a todo join the project.** `sqlc.embed(todos)` and `entities.name AS project`. A write (insert, update, soft delete) re-reads the row with the same join.
- **R4. A link is an event of its own**: `record_type` is `record_entities`, `record_id` is the ID of the link row, and the old and new value hold the entity ID and the record ref.
- **R5. A name with a kind.** A tool that gets a name needs the kind to create an entity. Input is `{name, kind}`; a bare name resolves only to an entity that exists, in any kind (when two kinds match, it is the ambiguity rule of the issue). A bare name with no match is refused with the list of kinds, because the kind of a new entity is a guess that cannot be undone by a rule.
- **R6. Admin pages.** `/admin/entities` (list, add, archive, merge) and `/admin/entities/{id}` (edit name, aliases, wiki page; the records that link to it). The todo form keeps the text field for the project, with a list of the project names.
